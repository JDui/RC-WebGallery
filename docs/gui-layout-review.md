# GUI 布局规范检查与修正

日期：2026-11-20。检查基线：`8168ea6`。

本轮围绕层级关系、位置对齐、几何居中、操作区占位、长内容及浮层越界进行源码检查，并修正可由模板、最终 CSS 级联和交互路径确定的问题。覆盖主界面、图库、详情、图片查看器、视频播放器、原帖与任务弹层、任务/日志、设置，以及内网连接和数据升级辅助页。

**验证边界：本环境不能启动真实浏览器进程，没有本轮实际截图、设备触控或像素对比结果。** 下文的“已修正”表示代码中的缺陷及对应约束已处理；不表示所有尺寸、字体和浏览器的实际视觉效果已经验收。纯光学居中、视觉轻重和留白观感仍需屏幕证据。

### 明确层级归属

`ui-tokens.css` 现在集中声明项目弹层级别，实际组件引用令牌：

| 同一 shell 堆叠上下文中的层 | 默认值 | 关系 |
| --- | --- | --- |
| 动态详情 | 60 | 盖住主界面 |
| 任务详情 | 70 | 高于普通详情 |
| 视频播放器 | 150 | 高于详情 |
| 原帖预览 | 160 | 能覆盖视频播放器 |
| 图片查看器 | 1700 | 高于内容弹层 |
| 通知 | 1800 | 媒体打开期间仍可见 |
| 内容操作菜单 | 19000 | 当前操作的最上层交互面板 |

帮助提示是挂到 `body` 的独立节点，使用 `--layer-help:1800`；它不与 shell 内部数值直接比较。原生 fullscreen 属于浏览器顶层，不能靠任意提高普通元素的 `z-index` 覆盖。

## 浮动位置与原生全屏

| 编号 | 原问题与触发条件 | 修正及验证 |
| --- | --- | --- |
| G16 | 内容菜单按固定220×100px估算位置，实际文字、字体和短视口可能改变尺寸；同为紧凑布局的旋转不会清除旧坐标 | 等 Alpine 显示帧后按实际尺寸定位，定位前保持不可见；按可见视口限制宽高和坐标，内容过高可滚动；视口变化后关闭旧菜单 |
| G17 | 帮助提示按布局窗口定位，忽略软键盘或缩放改变的可见范围 | 使用 `visualViewport` 的尺寸和偏移，缺失时回退到文档内容宽度及窗口高度；先约束尺寸再测量；可见视口变化后关闭提示 |
| G18 | 卡片在菜单显示帧之前被移除或复用，旧菜单仍显示并获取焦点 | 显示帧重新核验来源是否连接、文件夹及图片编号；失效时关闭。旧菜单回调不能修改较新的菜单 |
| G19 | 整页视频原生全屏时点击原帖或长按菜单，兄弟浮层实际位于 fullscreen 元素后面 | 复用 `exitFullscreenForOverlay()`，等待真实退出后打开浮层；保留实际点击节点，退出后再取来源几何。退出失败或1500ms仍未完成时，在播放器显示错误 |
| G20 | 两个不同浮层共享退出全屏 Promise，旧菜单可能盖住较新的原帖请求 | 接受原帖请求时取消现有及待打开菜单；接受菜单请求时使待打开原帖请求失效。两种先后顺序均由较新的请求生效 |
| G21 | 整页视频全屏中的普通通知仍位于浏览器顶层之外 | 在播放器内部展示同一份通知状态，与全局通知使用互斥条件；复用关闭处理，并隔离视频手势 |

全屏退出辅助方法兼容标准 Promise、WebKit 无返回值及完成事件，合并同时等待的退出请求，并清理事件监听和超时。关闭、切换内容及较新请求都可以使旧打开请求失效。

关于可见视口的依据：[MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport) 说明软键盘可缩小可见视口而不改变布局视口。本轮只在打开浮动层时采样，并在视口移动时关闭，避免持续追随视口位置的额外抖动。

## 已检查且保留

- 内网连接及数据升级页已有可增长主体、地址与错误断行、内容宽度下限释放；没有为本轮检查修改连接与升级业务。
- 页签、详情、图片及视频的来源动效仍使用现有动画系统；修正定位与层级时没有增加第二套变换控制。
- 手机视频翻页箭头的一组旧样式存在上下锚点同时声明，但模板会隐藏该分支；这不属于当前可见缺陷，未计入修复项目。
- 设置帮助、真实状态和错误的展示遵守仓库现有规则。

iOS 等浏览器的视频专用原生全屏由浏览器控制，不能叠加普通网页 HTML。本轮覆盖应用整页播放器全屏；不宣称控制系统播放器的界面。

本轮为源码修复并更新前端缓存修订号，没有构建新 Docker 镜像，也没有部署运行中的服务。
