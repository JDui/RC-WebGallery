# 重复图片检测与清理

检测沿用 256 位 dHash、宽高比限制和低对比度颜色校验，通过 BK 树查找候选图片。同一贴文内的图片不互相判重；不同贴文的候选图片采用最大数量一对一匹配，达到设置的图片数量阈值后建立贴文关联。遍历时优先选择较小的哈希距离，但不保证所有最大匹配中总距离最小。

贴文分组采用关联图的连通分量。A 与 B 相似、B 与 C 相似时可能出现在同组，不能据此推断 A 与 C 重复。显示的相似度是哈希距离换算值，不是重复概率。

## 清理规则

- 每张待清理图片都有直接匹配的保留图片，保留图片不会在同次清理中被删除。
- 沿用分辨率、发布时间、文件大小和稳定排序规则确定保留优先级。
- 同序号含实况、视频或多个媒体文件的组合不参与自动删除，避免图片匹配连带删除未验证内容。
- 生成清理计划时读取原图复核，执行后台清理前再次检查原图感知指纹及计划。图库或设置已变化、原图缺失或校验失败时停止任务，提示重新检测。缩略图只是检测候选的派生文件，其重建、重新编码或移除不会单独阻止原图未变的清理计划。
- 原图复核仍使用相同的感知哈希规则，不能排除所有视觉误判；执行前仍需查看相似图片。
- “仅保留此贴文”要求其直接覆盖其余贴文的全部图片，并且其余贴文不含实况或视频；执行前再次复核原图覆盖情况。部分重复时使用“仅清理重复”或逐条处理。
- 删除贴文后，对受影响分组重新计算连接关系和清理计划，避免残留已断开的分组或失效的保留依据。

## 缓存

缓存键包含算法版本、图片数量阈值以及媒体和贴文记录的判重依据，数量不变的原图路径、分辨率等记录更新也会使结果过期。时间戳、收藏、派生图路径和可从媒体记录推导的贴文媒体标志不参与过期判断，反复进入页面及这些展示维护不会单独使结果过期。检测期间判重依据发生变化时，生成的结果标记为过期。

重复图片清理、删除重复贴文及“仅保留此贴文”会在操作前记录预期删除范围。操作后逐条比较媒体及贴文记录，仅当差异恰好是本次删除且检测阈值未变时，更新剩余结果的缓存标记，允许继续处理下一组；已有过期状态、额外新增或替换媒体、设置变化仍要求重新检测。主动检测与重复项删除串行，页面读取在取得缓存锁后获取当前标记，避免并发请求用检测前的状态误判新结果。

主动检测及受影响分组重算会从当前文件刷新候选感知指纹，不复用数据库中的旧值。依次尝试小缩略图、兼容缩略图和原图，路径缺失或无法解码时回退；普通浏览仍使用分组缓存，不触发全库图片读取。这避免了旧指纹来自原图或旧缩略图时，反复检测仍出现“图片已变化”的误报。

数据库摘要采用流式计算，仍需要扫描记录；本次没有引入完整的增量检测。数据库之外直接替换文件不会立即更新缓存过期提示，清理执行前的文件复核会检查相关图片。原图复核增加了候选图片的读取和解码成本，实际性能需要图库基准测试。

算法缓存版本升级后需重新执行一次检测。

## 离线验证

在安装了开发依赖的 Python 环境中，从仓库根目录运行：

```sh
PYTHONPATH=docker_app python -m pytest -q docker_app/checks/test_duplicates.py
```

检查使用临时数据库和生成的图片，不访问真实图库或网络。
