# 数据结构升级与大图库加载

旧库仍可浏览，设置 → 维护 → 数据检查会显示“旧版数据（脏）”。升级由用户点击“升级数据结构并迁移目录”开始，不会在首页后台自动移动媒体。说明文字收纳在 `?` 中。“检查数据”仅检查数据库和原文件引用，不升级布局，也不自动删除缺失记录。

## 数据库布局

SQLite 本身使用分页 B 树，不会为一次首页请求读取整个 197 MB 数据库。本次按访问频率拆分模块，并减少请求中的全表聚合：

| 文件 | 内容 |
| --- | --- |
| `config/app.db` | 媒体记录、任务、站点来源、审核、Live Photo 持久配对等 |
| `config/control.db` | 设置、登录状态、订阅、侧栏计数缓存 |
| `config/browse.db` | 动态/图片浏览索引、页面缓存、分页边界查找表 |

发布时间与入库时间各有复合索引，入库时间从原 `folders.created_at` 保留。连续瀑布流分页记录边界并从索引定位；直接跳页无边界时使用偏移查询。内容修订计数用于缓存失效，不再在每次页面读取时统计所有内容。设置接口读取本地登录记录，联网验证保留在“检查 Cookie”按钮中。首页、订阅和设置初始化独立完成；数据统计仅显式刷新或清理任务时扫描磁盘。

拆表不会自动执行 `VACUUM`，因此原 `app.db` 文件大小可能暂时没有明显缩小；空闲页会被 SQLite 重用。这不等于每次读取这些空闲页。

## 媒体目录

```
data/images/bilibili-<订阅 UID>/<日期>/<原内容目录>/...
data/livephoto/bilibili-<订阅 UID>/<日期>/<原内容目录>/...
data/images/xhs-<来源 ID>/<日期>/<原内容目录>/...
data/livephoto/xhs-<来源 ID>/<日期>/<原内容目录>/...
```

没有来源信息时使用 `bilibili-unknown`。日期无法解析时使用 `unknown-date`。`sites` 保持现有布局。`folder_locations` 保存内容与实际目录的对应关系，新下载与重建索引也使用该表。迁移移动整个内容目录，保留原始媒体、配对标识和文件名；同时更新媒体、浏览索引、回收站与持久 Live Photo 配对中的路径。

数据统计会把媒体 `.thumbs/tiny` 中已废弃的缩略图算入垃圾文件；订阅头像、站点图标及其他仍在使用的文件受到保护。统计后仍需点击清理或启用定期清理才会删除。

升级会清除包含旧媒体地址的重复检测缓存，保留已忽略重复组的选择；可在重复内容页重新检测。历史 Live Photo 检查和手动选图也会按新的目录映射查找原文件。

## 独占、备份和中断恢复

应用保持单容器、单 Uvicorn worker，同一 `storage` 的第二个应用进程会拒绝启动。不要让其他版本容器、外部脚本或数据库编辑器同时写入这份数据。网络文件系统必须提供可靠的 SQLite 文件锁和同文件系统目录重命名语义。

开始后所有客户端进入独占进度页面，API 与媒体请求返回维护状态。已接受的 HTTP 请求（含流式响应与响应后台任务）结束后才迁移；队列、调度器和独立图标任务也必须停止写入。期间不能进入图库或修改设置。

1. 在 `config/before-data-layout-v2/` 保存迁移前数据库快照。已有快照在续跑时保留，不会用中间状态覆盖。
2. 使用 SQLite DELETE journal 与 FULL synchronous 在一个跨库事务内拆分表。迁移期间每次媒体引用更新也使用跨库事务。
3. `storage_moves` 先记录待执行目录移动，再重命名目录，最后将所有路径更新与完成标记一起提交。
4. 校验数据库结构、外键以及已下载媒体的原文件是否存在。缺失记录仅报告，不删除；它们可能在升级前就已经缺失。
5. 成功后写入布局版本 2，再恢复调度与页面。磁盘统计标记为待重新统计。

进程被杀或重启后，状态保留为“需要继续”，页面继续封锁。点击继续会重放未完成的移动：已经重命名但尚未提交路径的目录也可恢复。目标与原目录同时存在时停止，不覆盖任一方；修复冲突后继续。磁盘满、只读、路径越界和目录链接等错误会停止升级并保留错误信息。

自动数据库快照**不复制原始媒体**。如需完整回退，升级前应在停止应用后对整个 `config` 与 `data` 做同一时点的备份或 NAS 快照。不能只把旧 `app.db` 覆盖回去：媒体可能已经移动到新位置。回退应停止容器并成套恢复迁移前的 `config` 和 `data`，再运行相应版本。保留故障现场中的 `storage_moves`、状态文件、数据库和自动备份，方便定位；不要手动删除迁移状态来解封写入。

## 任务状态与空闲轮询

升级的真实状态来自 `/api/settings/data-upgrade`。`status=completed`、`version=2`、`blocked=false` 表示升级已完成。旧任务面板存在仅显示启动时“准备任务范围 / 1%”的问题；现已将升级阶段、进度、错误和结束状态同步到通用任务面板及事件日志，避免完成后继续显示运行中并使用较频繁的轮询。

健康检查原先每次会重复统计图库索引，并对媒体表分组及站点表关联计数。现已复用同一次请求的索引状态，按数据库内容版本在进程内缓存图库与站点统计。数据版本不变时只读取少量版本号；内容或索引设置改变后重新计算。版本号与统计来自同一只读事务快照，缓存命中不写持久缓存。

SQLite 的 `-wal` 和 `-shm` 文件属于正常运行文件，出现本身不代表迁移仍在执行。应用使用空闲连接保持日志打开，独占维护和服务退出时才关闭这些连接。文件反复消失的实际原因仍需结合服务生命周期与现场 I/O 记录判断，不能单凭目录截图归因。

## v11.4 缺失原文件检查与修复

旧检查把站点去重时已标为 `duplicate`、原文件已按设计删除的历史路径也统计为缺失。v11.4 检查明确排除这些记录，并单独显示排除数量。旧检查结果会显示“旧规则结果，待重新检查”，不会因升级程序版本就直接把缺失数清零。

维护中的“重新检查并修复缺失”只在用户点击后执行一次：

1. 重新扫描当前引用，排除站点去重记录，将真正缺失、空文件和无效路径写入 `config/data-check-report.json`，提供全部明细及分页查看。
2. 相同路径的图库、站点记录合并处理。图库原文件只从旧平铺目录、数据库目录映射或该内容应属的来源与日期目录中的唯一候选恢复，图片和实况目录分开匹配；其他日期的同名文件、站点标题和 slug 不用于猜测配对。
3. 没有本地原文件时，使用已有站点原文件下载地址，保留原路径与记录 ID。没有下载地址、小红书历史地址或网络失败会列出原因，需要重新同步相应来源。已去重图片不会重新下载。
4. 恢复内容先写独立临时文件，经图片格式或视频流校验并落盘后，通过硬链接原子创建目标；文件系统不支持硬链接时停止该项并报告，绝不退回覆盖已有原文件。已有空文件、目录冲突和多个候选也保留现场。
5. 逐项保存结果，成功和失败都结束本次任务，残留问题可以再次修复；中断后重新检查，只处理仍然缺失的原文件。如果上次在文件落盘后、数据库状态提交前退出，会先校验已恢复文件并补齐状态，不再下载。不会后台循环扫描、下载或删除未恢复的数据库记录。

修复同样使用全页接管并暂停后台写入。检查确认的是引用与文件存在性；网络补下还会校验媒体格式，不保证原站过期、下架或内容变更后仍可恢复同一原始字节。

空闲轮询隔离验证使用 3000 个动态、30000 条图片索引、50000 条媒体记录：两类统计预热后的 50 轮调用耗时约 75 ms，完整健康接口 20 次约 256 ms。连接级 SQL 跟踪未再出现聚合扫描或 DML；两组测试期间进程 `read_bytes` / `write_bytes` 增量均为 0，三个数据库及其 WAL/SHM 的大小和修改时间不变。四个统计读线程与 20 轮媒体、站点写入并行后，缓存结果与直接计数一致。这些结果属于本地 Linux Docker 合成测试，不代表真实 NAS 的磁盘读写情况。

2026-10-21 v11.4 修复验证由 GPT-6-Luna / xhigh 执行：Linux 迁移基础回归 15/15、迁移压力与异常恢复 22/22、原文件修复 19/19 通过。Windows 原文件修复 18 项通过，Linux 专用真实进程退出用例跳过；Windows 迁移基础回归 15/15 通过。新增修复测试涵盖 649 条去重记录排除、跨表共用路径、跨日期拒绝误配、错误网页与截断图片拒绝、无效视频、下载失败有界结束、完整明细以及中断续跑。真实强退用例在原子创建目标后调用 `os._exit(86)`，重启后确认文件保留、数据库状态恢复且 HTTP 下载次数仍为 1。所有数据均为隔离临时测试数据。

v11.4 补丁镜像复用本地 v11.3 的浏览器、媒体工具与 Python 依赖，仅替换应用源码。可在已有基础镜像的环境中复现：

```bash
docker build --pull=false --network none --platform linux/amd64 -f docker_app/Dockerfile.patch -t zzs-bili-gallery:11.4-amd64 .
```

导出的完整镜像 tar 包包含基础层，NAS 导入时无需预先保留 v11.3 镜像。更新使用原有 config、data 挂载，已经完成的数据结构升级无需重做；进入维护后点击“重新检查并修复缺失”复核旧结果。
