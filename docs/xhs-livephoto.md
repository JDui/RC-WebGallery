# 小红书 Live Photo

小红书本人点赞同步支持图文笔记中混排的静态图片和 Live Photo。每张实况对应一张静态图和一个 MP4，按原图片序号配对，使用图库已有的 Live Photo 播放功能。此归档格式不包含苹果相册 Live Photo 导入所需的配对元数据。

解析支持图片条目自身的 `stream`（包括 `masterUrl` 和 `backupUrls`），以及旧版 `live_photo`、`livePhoto`、`video` 子对象。视频笔记的封面不作为实况处理。地址刷新时保留已观察到的实况信息，避免静态详情快照覆盖待下载的实况；无地址或下载失败会保留静态图，记为部分归档，并进入“重试媒体”。已有文件继续复用。

升级时，旧版浏览器来源中 `ready` 且 `media_revision < 2` 的非视频笔记会一次性设为待检查，下一次同步或“重试媒体”重新解析。不会清空归档文件或点赞锚点。手动清单来源与手动排除状态保持原状。

## 验证

用户提供的真实样本：[上海万圣节街拍、可爱鬼出没](https://xhslink.cn/o/6khqpCG2S7w)，笔记 ID `6ad5eae30000000026033715`。2026-10-20 读取到 5 张静态图及 5 段实况视频，经生产媒体下载器下载成功。视频均为 1080×1440，时长分别为 2.80、2.93、2.73、3.00、2.36 秒。平台可能更新或下架资源，此记录代表本次样本验证结果。

同一样本还通过生产 FastAPI Worker 接口和主程序下载客户端完成 10 个文件归档，图库返回 5 组完整配对，5 段视频全片解码通过。Windows Chrome 在实际图库页面中打开第一组后，视频播放时间持续推进，分辨率为 1080×1440，页面无脚本错误。

本机 Docker 的 Chromium 沙箱启动受环境限制，未完成登录账号下的真实浏览器采集导航验收。上述完整链路测试仅在浏览器详情读取边界回放已捕获的真实 SSR 数据；资源请求、Worker HTTP 传输、磁盘归档、图库索引和网页播放使用实际实现，未关闭生产浏览器沙箱。当前未重打发布镜像。

21 项可重复的离线回归检查在 `docker_app/checks/test_xhs_livephoto.py`，不包含真实签名地址、登录凭据或网络依赖。在已安装应用依赖的 Linux 环境，从仓库根目录运行：

```sh
PYTHONPATH=docker_app python -m unittest discover -s docker_app/checks -v
```

覆盖五组实况结构、静态与实况混排、旧版结构、普通视频区分、详情延迟、缺失地址、备用地址、归档配对、部分失败补抓、缓存复用、旧版本迁移及配额中断。

真实样本载荷、下载文件和一次性验证脚本仅保存在被 Git 忽略的 `temp/xhs-livephoto/`。
